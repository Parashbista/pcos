# 9.3 AI Implementation

## 9.3.1 AI Algorithm Overview

The PCOS Health Tracker implements AI-powered health insights using a flexible multi-provider architecture. While the system doesn't use traditional pathfinding algorithms, it employs natural language processing and pattern recognition for health recommendations.

**AI Problem Formulation:**

**Initial State:** User health data (period cycles, mood patterns, sleep logs, symptoms)

**Goal State:** Personalized health insights and actionable recommendations

**Actions/Operations:**
- Data aggregation from multiple tracking modules
- Pattern analysis across time periods
- Correlation detection between health metrics
- Natural language generation of insights
- Recommendation prioritization

**Path Cost:** API call latency + computational processing time (typically 200-500ms per request)

**Success Criteria:**
- Relevant recommendations generated
- Insights based on user's actual data
- Actionable suggestions provided
- Response time < 2 seconds

## 9.3.2 PEAS Description

While the system doesn't involve mechanical devices, the PEAS framework applies to the AI recommendation system:

**Performance Measure:**
- Accuracy of health pattern detection
- Relevance of recommendations to user data
- User engagement with AI insights
- Response time (target: < 2 seconds)
- User satisfaction ratings

**Environment:**
- Mobile application interface
- User health database (MongoDB)
- External AI API services (Gemini/OpenAI/Anthropic)
- Network connectivity conditions
- User interaction patterns

**Actuators:**
- API requests to AI providers
- Database queries for user data
- Notification system for insights
- UI updates with recommendations
- Data export functionality

**Sensors:**
- User input data (period, mood, sleep, symptoms)
- Timestamp information
- User preferences and settings
- Historical tracking patterns
- Correlation metrics

## 9.3.3 Environment Portfolio

**Environment Characteristics:**

| Characteristic | Classification | Justification |
|----------------|----------------|---------------|
| Observable | Partially Observable | AI has access to logged data but not real-time physiological data |
| Deterministic | Stochastic | User health patterns vary; AI responses may differ |
| Episodic | Sequential | Current recommendations build on historical data |
| Static | Dynamic | User data changes daily with new logs |
| Discrete | Continuous | Health metrics are discrete entries over time |
| Single-agent | Multi-agent | Single AI system, but multiple users |

**Environment Constraints:**
- API rate limits (varies by provider)
- Network latency (50-500ms)
- Data privacy requirements
- Token limits per request (1024-4096 tokens)
- Cost per API call

## 9.3.5 Model Development

**AI Architecture:**

The system uses a **flexible adapter pattern** supporting multiple AI providers:

```
User Data → Data Aggregation → AI Service Factory
                                      ↓
                    ┌─────────────────┼─────────────────┐
                    ↓                 ↓                 ↓
              Gemini Adapter    OpenAI Adapter   Anthropic Adapter
                    ↓                 ↓                 ↓
              Gemini API        OpenAI API       Claude API
                    ↓                 ↓                 ↓
                    └─────────────────┼─────────────────┘
                                      ↓
                            AI Response Processing
                                      ↓
                            User Recommendations
```

**Provider Specifications:**

| Provider | Model | Max Tokens | Temperature | Response Format |
|----------|-------|------------|-------------|-----------------|
| Gemini | gemini-2.0-flash | 1024 | 0.7 | JSON/Text |
| OpenAI | gpt-3.5-turbo | 1024 | 0.7 | JSON/Text |
| Anthropic | claude-3-haiku | 1024 | 0.7 | Text |

**Prompt Engineering:**

**Health Insights Prompt Template:**
```typescript
const prompt = `
You are a health insights assistant for PCOS management.
Analyze the following user data and provide 3-5 actionable recommendations.

User Data:
- Average cycle length: ${cycleLength} days
- Recent mood trend: ${moodTrend}
- Average sleep: ${avgSleep} hours
- Top symptoms: ${symptoms.join(", ")}
- Mood-sleep correlation: ${correlation}

Provide recommendations in JSON format:
{
  "insights": [
    {
      "category": "sleep|mood|period|lifestyle",
      "priority": "high|medium|low",
      "recommendation": "specific actionable advice",
      "reasoning": "why this matters based on data"
    }
  ]
}

Focus on: sleep hygiene, stress management, cycle regularity, symptom relief.
Be supportive and evidence-based. No medical diagnoses.
`;
```

**Model Selection Rationale:**

**Gemini 2.0 Flash (Primary):**
- Fast response time (< 500ms)
- Cost-effective ($0.075 per 1M tokens)
- Good JSON formatting
- Suitable for health recommendations

**GPT-3.5 Turbo (Alternative):**
- Reliable performance
- Strong natural language generation
- JSON mode support
- Fallback option

**Claude 3 Haiku (Alternative):**
- Excellent reasoning capabilities
- Safety-focused responses
- Good for sensitive health topics
- Premium option

## 9.3.6 Optimization and Evaluation

**Optimization Strategies:**

**1. Prompt Optimization:**
- Iterative refinement of prompts
- A/B testing different prompt structures
- Token usage minimization
- Clear output format specification

**2. Response Caching:**
```typescript
// Cache similar requests to reduce API calls
const cacheKey = `insights_${userId}_${dateRange}`;
const cached = await cache.get(cacheKey);
if (cached) return cached;

const insights = await aiService.generate(prompt);
await cache.set(cacheKey, insights, 3600); // 1 hour TTL
```

**3. Batch Processing:**
- Aggregate multiple data points before AI call
- Reduce API calls from N to 1 per insight generation
- Cost reduction: ~80% fewer API calls

**4. Fallback Mechanisms:**
```typescript
async function getInsights(userData: UserData) {
  try {
    // Try primary AI provider
    return await aiService.generate(prompt);

}
```

## 9.3.7 AI Integration into Application

**API Integration Architecture:**

**Backend Integration:**
```typescript
// AI Service Initialization
import { getAIService } from './services/ai.service';

const aiService = getAIService();

// Health Insights Endpoint
router.post('/api/insights/generate', authMiddleware, async (req, res) => {
  const userId = req.user.id;
  
  // 1. Fetch user data
  const userData = await aggregateUserData(userId);
  
  // 2. Generate AI prompt
  const prompt = buildInsightsPrompt(userData);
  
  // 3. Call AI service
  const response = await aiService.generateJSON(prompt);
  
  // 4. Store insights
  await saveInsights(userId, response.data);
  
  // 5. Return to client
  res.json({ success: true, insights: response.data });
});
```
